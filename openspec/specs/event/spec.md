## Purpose

## Entities

### MapEventData

> `source/exvius/map_interaction_audit.js`

Represents an interactive event or triggerable object on an exploration map, responsible for
bounding rect hit-testing and executing associated action callbacks upon user touch.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| rect | number[] | Four-element bounding rectangle coordinates defining the touchable area on the map. |
| callback | string | Resolved type name of the callback handler executed when the event is triggered. |
| hit | boolean | Flag indicating whether a touch event successfully hit the interactive target area. |

**Relationships:**

- associates FieldTreasure (Map event data can represent interactable field objects such as treasure chests.)

### Event

> `source/exvius/restore_kira.py`

Represents a limited-time game event ('Vow of the Revived Legend') containing structured challenge
missions, stages, banners, and participation constraints.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| name | string | Title of the event |
| banner | string | Banner graphic asset identifier (e.g., event_6211.png) |
| stages | array | Sequence of event reward stages (e.g., ATK Pots, DEF Pots, MAG Pots, SPR Pots, MP Pots, HP Pots) |
| missions | array | List of mission identifier codes corresponding to progressive event difficulty levels |
| ruleCategories | string | Category constraint text restricting eligible units for the event |
| guide | string | Reference URL link for event strategy guidance |

**Relationships:**

- features Monster (Event missions host encounters against boss monsters)
- restricts-to Unit (Event limits team selection to units matching designated category requirements)

## Requirements

### Requirement: MapEventDataValidation

The system SHALL validate MapEventData according to these rules:
- Touch rectangle must contain 4 floating-point coordinates
- Hit status must be evaluated when touchAction is processed

#### Scenario: ProcessTouchInteractionOnMapEvent
- **GIVEN** A user interacts with the map view and touchEnded triggers touch action processing
- **WHEN** MapEventData::touchAction evaluates the touch against its touch rectangle
- **THEN** The hit flag is updated and the action callback type is resolved

### Requirement: EventValidation

The system SHALL validate Event according to these rules:
- Missions must map sequentially to stage levels from 1 to 8
- Event must specify valid rule categories restricting party entry

#### Scenario: BuildEventPackage
- **GIVEN** Event metadata, banner image, and stage definitions
- **WHEN** build() is executed
- **THEN** Manifests, localized records, and mission assets are bundled into the output package
