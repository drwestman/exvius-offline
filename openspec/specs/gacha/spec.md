# Gacha Specification

> Generated by openlore v1.2.0 on 2026-11-07 15:24

## Purpose

Defines core data models: GachaBanner, GachaBoxState, Player.

## Entities

### GachaBanner

> `source/server/player_state.py`

Represents a gacha summon banner offering unit and vision card prize pools for specific currency or
summon ticket costs.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| banner_id | string | Identifier for the gacha banner |
| cost_type | string | Type of cost required (currency or summon ticket ID) |
| cost_amount | integer | Amount of currency or tickets required to summon |
| pool | array | Unit roots and rarity tiers available to roll |

**Relationships:**

- awards Unit (Banner summons roll and award units into the player roster)
- consumes Item (Banner summons consume designated summon tickets)

### GachaBoxState

> `source/server/gacha_box.py`

Maintains persistent tracking of a player's summon history, drawn pool counts, step-up progress, and
lap completions for a banner.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| box_id | string | Identifier of the box pool being tracked |
| detail_id | string | Current active detail or tier identifier for the player |
| counts | object | Mapping of drawn item/unit identifiers to counts consumed from the box pool |
| completed_laps | integer | Total number of step-up laps completed by the player |
| daily_counts | integer | Number of daily rolls used by the player within the current gacha period |

**Relationships:**

- belongs to GachaBanner (Represents draw state specifically bound to a banner and box pool)
- belongs to Player (Associated with the player whose summons are tracked)

### Player

> `source/server/gacha_box.py`

Represents the user entity possessing currencies, summon tickets, and inventory, who performs gacha
rolls.

**Properties:**

| Name | Type | Description |
|------|------|-------------|
| id | string | Unique identifier of the player account |
| currencies | object | Balances of currencies used to roll banners, such as lapis or gold |
| item_counts | object | Quantities of inventory items and summon tickets owned by the player |

**Relationships:**

- rolls GachaBanner (Player consumes tickets or currency to summon on banners)
- owns GachaBoxState (Player holds individual progress states across various gacha boxes)

## Requirements

### Requirement: GachaBannerValidation

The system SHALL validate GachaBanner according to these rules:
- Player must possess required currency or summon ticket count prior to rolling
- Summons must be executed within the banner's active validity period
- Summon count must not exceed daily or lap step limits authored on the banner

#### Scenario: SummonFromGachaBanner
- **GIVEN** An active banner and sufficient ticket or currency balance
- **WHEN** roll_gacha() is executed
- **THEN** Summon cost is deducted, prizes are selected from the expanded pool, and awarded units are added to
player state

### Requirement: GachaBoxStateValidation

The system SHALL validate GachaBoxState according to these rules:
- Drawn counts for limited items in the box cannot exceed total pool availability
- Step index cannot exceed the maximum steps configured for the lap

#### Scenario: QueryBoxState
- **GIVEN** An active player and a selected gacha banner
- **WHEN** state(player, banner) is called
- **THEN** The player's current draw counts, step position, and completed laps are returned

### Requirement: PlayerValidation

The system SHALL validate Player according to these rules:
- Currency and item counts cannot be negative after roll expenditures
- Player must have sufficient inventory capacity to receive granted units and vision cards

#### Scenario: RollGachaAndReceiveRewards
- **GIVEN** A player with required ticket or currency balance
- **WHEN** player.roll_gacha() is executed
- **THEN** Currency or tickets are deducted and rewarded units, vision cards, or items are added to player
inventory
